# Томсон — бронирование фотостудии

PWA-приложение для управления бронированиями фотостудии «Томсон».

Приложение предназначено прежде всего для администратора студии: быстро создать бронь, увидеть загрузку залов, проверить статус оплаты, открыть карточку клиента, подготовить сообщение и работать с расписанием из одного интерфейса.

> **Статус:** проект находится в активной разработке. Основной интерфейс календаря и PWA уже реализованы. Интеграция с Google Calendar вынесена в отдельный Cloudflare Worker и развивается отдельно.

---

## Возможности

### Календарь

- месячный, недельный и дневной режимы;
- переход между датами;
- быстрый переход к нужному месяцу и году;
- отображение текущего дня;
- выделение выходных;
- просмотр одного зала или всех залов одновременно;
- временная сетка для дневного и недельного представления;
- создание брони долгим нажатием в календаре;
- визуальное отображение пересекающихся и занятых интервалов;
- отображение событий, полученных из Google Calendar.

### Залы

В приложении предусмотрены три зала фотостудии:

- **Эдисон**
- **Сфера**
- **Вегас**

Для каждого зала предусмотрены собственные настройки, цвет и данные, необходимые для формирования бронирования и сообщений.

### Бронирование

Карточка бронирования содержит основные данные заказа:

- имя клиента;
- телефон;
- дата;
- время начала и окончания;
- количество гостей;
- выбранный зал;
- мессенджер для связи;
- статус оплаты;
- дополнительные теги;
- комментарии;
- стоимость.

Статусы оплаты используются в компактной форме:

| Обозначение | Значение |
|---|---|
| `-` | предоплата не внесена |
| `.` | внесено 50% |
| `..` | внесено 100% |

Дополнительные теги позволяют быстро отметить особенности заказа, например танцы, спот и другие условия съёмки.

### Сообщения клиенту

Приложение формирует готовые сообщения на основании данных бронирования и настроек конкретного зала.

Поддерживается сценарий, при котором текст можно подготовить в приложении, скопировать и отправить клиенту через нужный мессенджер.

### Google Calendar

Интеграция с Google Calendar является отдельным слоем системы.

Основная схема:

```text
THOMCOH_OS (PWA)
        │
        │ HTTPS API
        ▼
tomson-auth (Cloudflare Worker)
        │
        │ OAuth / Calendar API
        ▼
Google Calendar
```

Для студии используются отдельные календари залов. Приложение умеет получать события Google Calendar через Worker и отображать их в собственном календарном интерфейсе.

OAuth-токены не хранятся в клиентском коде PWA: серверная часть использует Cloudflare KV для хранения токенов, а секрет клиента Google хранится как Cloudflare Secret.

На этапе разработки используется отдельный тестовый календарь, чтобы проверять интеграцию без риска для рабочих бронирований.

> Важно: `tomson-auth` не входит в этот GitHub-репозиторий. Это отдельный Cloudflare Worker, расположенный локально в проекте `THOMCOH_OS/tomson-auth`.

### PWA

Приложение устанавливается как веб-приложение:

- **iOS / Safari:** «Поделиться» → «На экран Домой»;
- **Android / Chrome:** меню браузера → «Установить приложение» / «На главный экран».

После первой загрузки service worker кэширует необходимые ресурсы, поэтому интерфейс может работать без постоянного сетевого соединения.

## Архитектура

На текущем этапе проект намеренно остаётся лёгким: основной клиент — обычный HTML/CSS/JavaScript без frontend-фреймворка и сборщика.

```text
┌─────────────────────────────────────────┐
│               THOMCOH_OS                │
│                                         │
│  PWA                                     │
│  ├── календарь                           │
│  ├── бронирования                        │
│  ├── настройки                            │
│  ├── сообщения                            │
│  └── локальный cache/state                │
└───────────────────┬─────────────────────┘
                    │
                    │ HTTPS
                    ▼
┌─────────────────────────────────────────┐
│            tomson-auth                   │
│          Cloudflare Worker               │
│                                         │
│  ├── Google OAuth                        │
│  ├── Calendar API proxy                 │
│  └── KV TOKENS                           │
└───────────────────┬─────────────────────┘
                    │
                    ▼
             Google Calendar
```

### Клиентская часть

Основная PWA находится в `index.html`. Стили и JavaScript также находятся непосредственно в этом файле, что упрощает разработку и развёртывание небольшого внутреннего приложения.

Настройки и локальные данные сохраняются в браузере. Это позволяет приложению продолжать работу без отдельной базы данных на раннем этапе разработки.

### Серверная часть

`tomson-auth` выполняет функции промежуточного сервера между PWA и Google Calendar API.

Worker отвечает за:

1. запуск Google OAuth;
2. получение authorization code;
3. обмен code на access/refresh tokens;
4. хранение токенов в Cloudflare KV;
5. обновление access token после истечения срока действия;
6. выполнение запросов к Google Calendar API от имени подключённого аккаунта.

## Локальные данные

На текущем этапе приложение использует браузерное хранилище для локального состояния.

Это сделано намеренно: PWA можно запустить без отдельного backend/database слоя, а архитектуру синхронизации с Google Calendar развивать независимо.

Текущая модель подходит для прототипирования и внутреннего использования, но не является полноценной многопользовательской базой данных.

В дальнейшем возможен переход к единому серверному источнику данных, если появится необходимость в общей базе бронирований, истории изменений, ролях пользователей и синхронизации между несколькими устройствами.

## Запуск локально

Проект не требует Node.js, npm или сборщика для запуска самого PWA.

Самый простой вариант — открыть `index.html` через локальный HTTP-сервер.

Например, если установлен Python:

```bash
cd /path/to/TOMCON_2
python3 -m http.server 8080
```

После этого открыть:

```text
http://localhost:8080/
```

Использование HTTP-сервера предпочтительнее прямого открытия `file://`, поскольку service worker и часть PWA-функций требуют нормального origin.

## Cloudflare Worker

Worker не должен храниться вместе со статическим PWA в репозитории GitHub Pages.

Локальная структура проекта разработки:

```text
THOMCOH_OS/
├── ... основной проект ...
└── tomson-auth/
    ├── src/
    │   └── index.js
    └── wrangler.toml
```

Worker разворачивается через Wrangler.

Основные команды:

```bash
cd /Users/alexey/Documents/Project_Git/THOMCOH_OS/tomson-auth

npx wrangler login
npx wrangler whoami
npx wrangler deploy
```

### Cloudflare KV

Для хранения OAuth-токенов используется KV namespace с binding:

```text
TOKENS
```

Идентификаторы и секреты не следует переносить в публичную документацию или клиентский JavaScript.

## Безопасность

Архитектура разделяет публичный клиент и секреты Google OAuth:

```text
PWA
 │
 │ public
 ▼
GitHub Pages

Google Client Secret
 │
 │ private
 ▼
Cloudflare Worker
```

В частности:

- `CLIENT_SECRET` хранится в Cloudflare Secret;
- refresh token хранится на стороне Worker в Cloudflare KV;
- PWA не содержит Google Client Secret;
- OAuth callback проходит через Worker;
- тестирование записи в календарь проводится на отдельном календаре до подключения рабочих данных.

## Принципы проекта

### Простота вместо избыточного стека

Проект намеренно не использует React, Vue, Angular или другой frontend-фреймворк. Для текущего масштаба обычного HTML/CSS/JavaScript достаточно.

### PWA-first

Приложение должно ощущаться как установленное мобильное приложение, но оставаться обычным веб-приложением, которое можно открыть по ссылке.

### Настройки вместо хардкода

Разовые параметры студии, залов, сообщений и реквизитов должны постепенно переноситься в настройки, а не размазываться по коду.

### Google Calendar как интеграционный слой

Google Calendar используется как рабочая система расписания, а `tomson-auth` изолирует OAuth и серверный доступ к API от публичного PWA.

### Безопасная миграция

Новые функции, особенно запись и изменение событий Google Calendar, сначала тестируются на отдельном календаре и только после проверки подключаются к рабочим данным.
